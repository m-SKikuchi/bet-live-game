# 忘年会ダービー / BET LIVE

スマートフォンから参加できる、リアルタイム予想・ベットゲームです。

主催者がPCの管理画面からゲームを進行し、参加者はスマートフォンなどのWebブラウザーからルームへ参加します。

通信には Socket.IO を使用し、ベット、オッズ、ランキング、ゲーム状態などをリアルタイムに同期します。参加者向けと主催者向けで配信する状態を分け、参加者に非公開のオッズ値は参加者向け通信には含めません。

## 6. 問題データ

問題は `questions.json` に記述します。

例：

```json
{
  "questions": [
    {
      "id": 1,
      "question": "日本で最も高い山は？",
      "choices": [
        "富士山",
        "北岳",
        "奥穂高岳"
      ]
    }
  ]
}
```

### 制約

- `questions` は配列
- 問題は1問以上必要
- `question` は空文字不可
- `choices` は2個以上必要
- 選択肢は空文字不可
- すべての問題で選択肢数を統一する

選択肢数は主催者画面では設定しません。

`questions.json` の内容から自動的に決定されます。

ルーム作成時の問題数が `questions.json` の登録問題数を超えた場合、実際のラウンド数は登録問題数までになります。


## 7. ゲーム状態

ゲームは以下の状態で管理されています。

```text
LOBBY
  ↓
QUESTION_READY（問題表示・ベット開始待ち）
  ↓
BETTING（ベット受付中）
  ↓
BETTING_CLOSING（締切演出後のカウントダウン中・ベット受付可）
  ↓
BETTING_CLOSED
  ↓
ANSWER_SET
  ↓
RESULT
  ├─→ QUESTION_READY（次の問題を表示）
  └─→ FINAL_WAITING（外部結果発表待ち）
          ↓ 主催者が公開操作
        FINISHED（最終ランキング公開）
```

### LOBBY

ルーム作成直後です。

参加者の参加を待つ状態です。

### QUESTION_READY

問題と選択肢を表示し、主催者が内容を確認するフェーズです。ベットはまだ受け付けません。主催者が「ベット開始」を押すとBETTINGへ移行します。

### BETTING

ベット受付中です。問題文・選択肢はロックされますが、締切カウントダウン開始前までは問題編集画面から現在の問題の制限時間を変更できます。

### BETTING_CLOSING

主催者が「ベット締切」を押した後、締切演出アニメーションが終了してからカウントダウンが始まります。カウントダウン中もベットを受け付けます。時間は問題ごとの設定値（初期値10秒、1～600秒）を使用します。締切時刻はサーバー側で管理し、時刻到達時に自動でBETTING_CLOSEDへ移行します。

### BETTING_CLOSED

ベット締切後です。

### ANSWER_SET

正解設定済みです。

### RESULT

配当計算・結果公開済みです。

### FINAL_WAITING

最終問題の結果確定後、主催者が「外部結果発表待ちへ」を押すと移行します。参加者画面には待機アニメーションを表示し、最終ランキングはまだ表示しません。外部ツールで優勝者等の発表を行います。

### FINISHED

主催者が「最終結果を参加者に公開」を押すと移行します。参加者画面には本人の最終得点・順位と、参加者全員のランキングを表示します。同点の場合は同順位として扱います。


## 8. 参加者管理

参加者には参加者番号が発行されます。

初回参加では、

- 名前
- ルームID

を使用します。

参加者番号を空欄にすると、新規参加者として登録されます。

再ログインでは、

- 参加者番号
- 名前
- ルームID

を使用します。

使用している参加者データ内に登録されている参加者番号と名前が一致した場合に再ログインできます。


## 9. 参加者データセット

ルーム作成時には以下の3パターンを利用できます。

### 既存データを使用

以前作成した参加者データを選択します。

登録済みの参加者番号を再利用できます。

### 新規データを作成

「新しい参加者データ名」を入力すると、新しい参加者データセットを作成します。

例：

```text
2026年忘年会
```

### 一時データを使用

既存データも新規データ名も指定しなかった場合は、

```text
空の参加者データ
```

がルーム専用データとして作成されます。


## 10. ベット処理

ベット可能なのは、

```text
BETTING
```

状態のみです。

ベット額は、

- 1以上の整数
- 利用可能ポイント以下

である必要があります。

同一ラウンドで同一参加者が再度ベットした場合、以前のベットを取り消し、新しいベットへ置き換えます。

その際、以前のベット額はいったん利用可能ポイントへ戻してから、新しいベット額を差し引きます。


## 11. 二重送信対策

参加者画面では、ベット送信中にベットボタンを無効化しています。

さらに、ベットごとに `crypto.randomUUID()` で `idempotencyKey` を生成します。

サーバー側でも使用済みキーを管理しており、同一ベット要求の重複処理を防止します。


## 12. オッズ計算

各選択肢のオッズは基本的に、

```text
配当原資 ÷ その選択肢へのベット総額
```

で計算します。

問題ごとに「オッズを参加者画面に表示する／しない」を設定できます。非表示にした場合、参加者向けの状態データにはオッズ値を含めません。一方、主催者画面には主催者認証済みの専用状態を配信するため、非公開設定の問題でも常にオッズが表示されます。この設定は画面表示・情報配信のみを制御し、オッズ計算や配当計算には影響しません。

小数点以下2桁まで保持します。

その選択肢へのベットが0の場合は、オッズなしとして扱います。


## 13. 配当計算

正解選択肢へのベット総額に対する各参加者のベット比率を使って、配当原資を分配します。

整数ポイントで処理するため、小数部分は切り捨てます。

丸めによる余りについては最後の対象ベットへ加算し、配当原資全体が一致するようにしています。


## 14. キャリーオーバー

正解者が0人の場合、そのラウンドのベット総額をキャリーオーバーへ加算します。

通常ラウンドではキャリーオーバーは配当に使用されません。

最終ラウンドのみ、

```text
最終ラウンドのベット総額
+
それまでのキャリーオーバー
```

を配当原資として使用します。

最終ラウンドでキャリーオーバーが配当に使用された場合、キャリーオーバーは0になります。

## 16. Socket.IO

リアルタイム処理にはSocket.IOを使用します。

主なイベント：

```text
subscribe
state
roomError
bet
host
```

### subscribe

クライアントを指定ルームへ参加させます。

### state

最新ゲーム状態をクライアントへ送信します。

### roomError

存在しないルームなど、ルーム関連のエラーをクライアントへ通知します。

### bet

参加者からベットを送信します。

### host

主催者操作を送信します。

主なaction：

```text
start
closeBetting
setAnswer
finalize
next
finish
```


## 17. データ保存

標準では、

```text
data/
```

へ保存します。

環境変数 `DATA_DIR` が指定されている場合は、そのディレクトリを使用します。

保存ファイル：

```text
rooms.json
participant-data.json
csv/
```

これらは実行時データです。GitHubには登録せず、起動時に自動生成します。Renderでは `DATA_DIR` に指定したPersistent Diskへ保存してください。

JSON保存時には一時ファイルへ書き込み後、正式ファイルへリネームすることで、書き込み途中のJSON破損を抑制しています。

## 20. 開発時の注意事項

### questions.json変更後

問題データはサーバー起動時に読み込まれます。

変更後はサーバーを再起動してください。

### dataを変更する場合

手動編集前に、

```text
data/rooms.json
data/participant-data.json
```

をバックアップしてください。

### ゲーム状態を変更する場合

状態遷移は `server.js` の `isAllowedTransition()` と、主催者画面側の操作定義の両方を確認してください。

### 配当ロジックを変更する場合

主に以下を確認します。

```text
calculatePool()
calculateOdds()
settle()
createParticipantChanges()
```

## 完全版での変更
- ルーム作成時の問題数入力を廃止
- 問題表示後にベット開始待ちフェーズを追加
- 問題ごとの締切カウントダウン時間（初期値10秒、1～600秒）を設定可能
- 締切演出アニメーション終了後にカウントダウン開始
- 正解発表で正解選択肢・獲得点数・クイズ前後のポイントを表示
- 登録済み全問題を使用
- ルーム作成後、ゲーム開始前に主催者画面で問題文と選択肢を追加・変更・削除可能
- 編集内容はルームデータへ保存
- スマートフォン向け入力・ボタン・数値ステッパー対応

### 問題ごとのオッズ表示設定
主催者は問題編集画面で各問題の「オッズを参加者画面に表示する／しない」を個別に設定できます。チェックを外すと参加者画面では倍率が非表示になりますが、主催者画面では常に倍率を確認できます。ベット受付や配当計算は通常どおり行われます。
